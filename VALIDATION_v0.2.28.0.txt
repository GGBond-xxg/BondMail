Scope validated
---------------
This release reduces the first-open timing differences between messages using generic scheduling,
not sender-specific download rules:
- initial small-body prefetch window increased to 32 messages;
- process-restart warm window increased to 12 messages after a 1.8 second settling delay;
- the stable visible viewport is prefetched in batched IMAP BODY requests;
- visible-window automatic download retains the existing 128 KiB ceiling;
- tapping a message cancels lower-priority warming and starts an interactive body load before the
  detail destination is composed;
- prepared local HTML document cache increased from 32 to 64 entries;
- one fully committed pooled WebView page can be retained for an instant reopen of the same message.

The existing provider-aware HTML classification remains limited to layout compatibility. It does
not select which message body is downloaded first. First-open time can still differ when the body is
already cached, the message is larger than 128 KiB, MIME structure is more complex, the IMAP server
responds slowly, or remote images must be fetched.

Gmail-style message detail changes validated:
- the detail app bar uses the page background with no tonal or shadow elevation;
- the app bar title slot is empty while back, star and overflow actions remain present;
- the message subject is rendered as a multiline content heading above the sender block;
- loading state shows the real subject and sender information at the same final positions;
- the sender block and subject use the same page background;
- the reply, forward, share and delete bottom dock remains unchanged.
