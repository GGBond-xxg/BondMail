# BondMail v0.2.23.0

## 邮件详情顶部安全区

- 邮件正文不再依赖固定 `96dp` 顶部留白，而是按“设备状态栏实际高度 + 64dp 详情顶栏 + 12dp 安全间距”动态计算。
- 加载骨架与最终 HTML 共用同一个顶部位置；刘海、挖孔和较高状态栏设备不会再让顶栏阴影压住发件人区域。
- 发件人区域最小高度调整为 `92dp/px`，发件人区域与正文之间统一保留 `10dp/px`。
- WebView 文档缓存升级为 `layout-v16`，旧的错误排版缓存不会继续复用。

## GitHub 等短邮件滚动

- 一次 `ACTION_DOWN` 到 `ACTION_UP/CANCEL` 始终由正文 WebView 持有，Compose 父层不能在拖动中途抢走手势。
- 短邮件增加不可见的底部滚动余量和稳定的最小文档高度，即使正文不足一屏也能产生明确的拖动、回弹与过滚反馈。
- 顶部栏和底部操作 Dock 除了监听真实 `scrollY`，还会监听手指累计位移；短邮件真实滚动距离很小时仍能按方向收起和恢复 Chrome。
- 新增 `BondMail-Web` 手势诊断日志，记录 `travel`、`scrollY`、内容高度、视口高度、缩放比例和上下滚动能力。
- WebView 回收到缓存池时继续清除触摸、滚动和页面监听，下一封邮件不会继承上一封的手势状态。

## Cloudflare 等桌面 Newsletter 完整显示

- 新增 `FLUID` 与 `DESKTOP_SCALED` 两种邮件文档布局。
- 对浅层、显式声明约 `480–900px` 宽度的 newsletter/table 模板进行桌面画布识别；常见约 `600px` 的邮件保留原始列关系，再整体缩放到手机可用宽度。
- 桌面画布只包裹原始邮件正文，BondMail 自己的发件人头部保持正常字号和宽度。
- 缩放比例按当前 Android 窗口宽度计算并写成明确数值，避免依赖浏览器对 CSS 除法表达式的兼容性；旋转或分屏宽度变化时会生成对应布局缓存。
- 桌面画布使用 `NORMAL` 排版算法，避免 Chromium 文字自动放大后再次破坏表格列宽；普通邮件继续使用 `TEXT_AUTOSIZING` 和手机宽度流式重排。
- 图片、视频和 SVG 仍受可用宽度限制；普通邮件继续处理固定宽度、深层表格、长链接、引用块和无换行文本。
- 日志会输出最终布局类型、检测到的桌面宽度和顶部安全区，便于继续定位特殊模板。

## K-9 式首次同步体验

本版根据同一 163 邮箱的 K-9 首次同步日志重做首屏提交策略。K-9 的关键做法是“网络批量 FETCH，但每完成一封就保存并通知列表”，而不是为每封邮件重新建立网络请求。

BondMail 当前流程：

1. 复用添加账户时已经认证的 IMAP Store，减少账户验证后立刻再次 TLS 登录。
2. 初次同步仍以一次批量 FETCH 读取最近窗口的邮件头，不为列表动画增加几十次网络往返。
3. 最新 8 封邮件先按约 `28ms` 间隔逐封写入 Room，让第一条尽快出现；剩余邮件按 4 封一组、约 `56ms` 节奏继续提交。
4. 首页新增行使用轻微淡入和 `10dp` 上移归位动画；已有 Room/内存缓存的行不重复播放进入动画。
5. 首次同步结束后，对最近最多 8 封邮件执行一次批量正文预取；`128 KiB` 以下的小邮件一起获取，大邮件保留邮件头并在用户打开时按需下载。
6. 正文批量返回后逐封写入 Room；列表正在滚动时会等待短暂空闲窗口，避免后台 MIME 解析和预览更新影响滚动帧率。
7. 初次同步中途进入后台或进程被结束时，已提交的邮件继续保留；只要 `lastSyncAt` 尚未完成，恢复过程仍属于历史基线，不会把剩余历史邮件当成新消息通知。
8. 普通后续同步保持原来的增量与通知语义，不把为了动画而分批提交的历史邮件发布为系统通知。

## 日志与隐私

- 更新 `docs/K9_BONDMAIL_LOG_COMPARISON.md`，增加首次添加账户、首次同步和正文滚动的分开抓取流程。
- K-9 的完整 Debug 日志可能包含邮箱地址、服务器配置，个别版本甚至会打印应用专用密码；发送前必须撤销暴露的授权码并使用脱敏副本。
- BondMail 的关键日志使用 `BondMail`、`BondMail-IMAP`、`BondMail-SMTP`、`BondMail-Perf`、`BondMail-Web` 标签，不记录授权码、密码或 Token。

## Microsoft OAuth

- 新增 `docs/MICROSOFT_OAUTH_PREPARATION.md`，整理 Entra 目录、Android 包名、签名哈希、Redirect URI、MSAL Configuration JSON 和 Exchange Online 委托权限的准备步骤。
- Microsoft OAuth 登录代码本版仍未接入；项目不会使用普通密码方案冒充 OAuth，也不会要求把 Client Secret 放入 APK。

## 版本与数据

```text
versionCode = 39
versionName = 0.2.23.0
Room 数据库版本 = 5
HTML 文档缓存 = layout-v16
```

本版没有数据库结构变化。覆盖安装会保留账户、邮件、正文缓存、联系人、发件箱、附件任务和设置。
