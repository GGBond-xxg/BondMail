# BondMail v0.2.30.0

## 已读状态不再被后台同步改回未读

真机日志确认，Gmail 邮件被打开后重新变成未读并非服务商特例，而是本地操作与周期同步之间的通用竞态：周期任务先从服务器取得一批 FLAGS，用户随后打开邮件并将本地状态改为已读，但较慢的同步任务稍后才把先前取得的旧 FLAGS 写入 Room，于是界面又恢复为未读。Outlook、163 以及其他 IMAP 服务商都可能触发相同问题。

本版为每个账户增加本地 FLAGS 版本：

- 同步开始前记录账户当前版本；
- 用户打开邮件、切换已读/未读或星标时立即推进版本；
- 同步准备写入远端 FLAGS 时再次核对版本；
- 版本已变化时丢弃整批过期 FLAGS，只提交文件夹游标和同步时间；
- 下一次同步会读取服务器的最新状态；
- 已读与星标操作在本地先即时反馈，远端提交失败时恢复原状态；
- 用户 FLAGS 操作与同账户的同步通道串行提交，避免新同步在远端操作完成前取得旧值。

这套保护不区分 Gmail、Microsoft 或授权码邮箱，适用于全部 IMAP 账户。Debug 日志新增：

```text
read flag optimistic ...
seen success ...
read flag committed ...
skip stale flag snapshot ...
read flag rollback ...
```

## 首次打开字体变化与再次打开闪帧

录屏逐帧对比显示，首次打开时 Compose 占位层先绘制了真实主题和发件人，随后 WebView 又使用 Chromium 字体排版绘制相同文字。即使字号接近，两套字体引擎的字重仍不同，因此视觉上会从粗变细。

本版将加载层改为中性 Gmail 形状骨架：

- 加载阶段不再绘制第二套真实主题、发件人或邮箱文字；
- Chromium 完成可见帧后一次显示最终正文；
- 不存在两套相同文字互相替换，因此不会再出现粗细变化；
- 进度条延迟出现，正文很快时不会闪出加载反馈。

再次打开同一封邮件时，已提交的 WebView 页面仍然复用，但现在只有在 AndroidView 完成重新挂载后的下一帧才显示。挂载前由稳定骨架覆盖，避免先暴露空白 WebView 表面。

另外，点击邮件时会同步保存一份最多 16 条的详情初始快照，再执行导航。导航目的页即使在同一帧开始组合，也能立即获得主题和发件人信息，不会因 Compose 状态尚未提交而生成一帧空详情页。
