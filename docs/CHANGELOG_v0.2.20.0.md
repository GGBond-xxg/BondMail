# BondMail v0.2.20.0

本版根据 `Record_2026-07-24-18-59-05` 录屏和用户提供的 Gmail 对比截图，集中处理首页搜索按钮滚动轨迹不一致、邮件详情发件人信息首帧闪动、主页面滚动逻辑重复、邮件/联系人主体样式与对比图不一致，以及浅色模式强调按钮缺少悬浮感的问题。

## 1. 搜索按钮与顶栏同步收回

旧实现长期把收起状态的搜索按钮绘制在顶栏外部 Overlay 中，再根据顶栏位置单独推算 Y 坐标；抽屉、更多和添加邮箱则直接属于顶栏，因此同一次滚动会走两条不同的位置更新路径。

本版调整为：

- 收起状态的搜索按钮直接放回抽屉、更多和添加邮箱所在的同一顶栏 `Row`。
- 四个入口由同一个 `graphicsLayer.translationY` 位移，不再分别估算收起位置。
- 只有搜索容器正在展开或收回时，Overlay 才临时接管搜索 Surface。
- Overlay 从真实按钮的 `boundsInRoot()` 开始插值；普通滚动不再绘制第二个独立搜索按钮。
- 搜索展开期间始终只有一个可见搜索图标，关闭时先完成容器回收，再恢复源按钮并处理键盘。

因此慢速拖动、快速 fling、反向恢复和回到列表顶部时，搜索、更多、添加邮箱与左侧抽屉入口会保持同一速度、同一水平基线和同一离场方向。

## 2. 首页、联系人和设置复用同一滚动 Chrome 控制器

新增 `ui/motion/ChromeScroll.kt`：

- `ObserveLazyListChromeVisibility` 统一处理滚动方向、52dp 累计阈值、方向反转清零、滚动结束复位和列表顶部强制恢复。
- `animateChromeOffset` 统一使用 `BondMotionDuration.ChromeReveal` 与强调加速/减速曲线，驱动顶部栏和底部 Dock 越过屏幕边界。

具体行为：

- 首页继续同时收起顶栏和共享底部 Dock。
- 联系人向上滚动时，顶部搜索栏和共享底部 Dock 同时收起；反向滚动同时恢复；回到顶部强制显示。
- 设置页没有固定标题，只让共享底部 Dock 按相同规则收起和恢复。
- 主 Tab 切换时父层恢复 Chrome，避免继承上一个页面的隐藏位置。
- `AnimatedContent` 的离场页面不再有权修改新页面的 Chrome 状态。
- 底部 Dock 的可见状态由 `MainTabs` 单一持有，三个主页面不再复制动画参数。
- 邮件详情继续通过 WebView 滚动回调判断方向，但顶部栏和底部操作 Dock 复用同一个位移动画函数。

## 3. 邮件列表和联系人主体改为紧凑 Gmail 风格

本次只调整列表主体视觉，不改抽屉、账户、同步、点击、长按、星标、左右滑动语义或写信流程。

共享内容 Token：

- 邮件、联系人、搜索结果和左右滑动背景统一使用 `MailContentDefaults`。
- 卡片圆角统一为 6dp，行间距统一为 3dp，左右留白统一为 10dp。
- 低圆角与紧凑间距对应用户提供的深色 Gmail 对比图，不再使用大号药丸卡片。

邮件行：

- 舒适/标准/紧凑高度为 104/96/82dp，头像为 52/48/42dp。
- 发件人、主题、摘要分别使用 16sp、15sp、14sp，行高和字重重新分层。
- 未读使用主文字色与更明确字重；已读使用 `onSurfaceVariant`，不再依赖蓝色未读圆点。
- 已读使用 `surfaceContainerLowest`，未读使用轻量更高的 Surface；不为每一行叠加昂贵阴影。
- 时间、星标和左右滑动背景继续与当前密度及手势逻辑兼容。

联系人行：

- 使用相同 6dp 圆角和 3dp 间距，最小行高 78dp，品牌头像 46dp。
- 姓名为 16sp 中等字重，邮箱为 14sp 次级正文。
- 顶部 60dp 搜索容器成为可收回顶部 Chrome，列表内容从其下方开始。

## 4. 邮件详情发件人信息不再闪动

旧版 Compose 占位层先绘制真实发件人名称、邮箱和收件账户；WebView 随后用另一套字体度量与截断规则再次绘制同一文字。两套渲染器交接时会出现名称粗细变化、邮箱先完整后变成 `...` 或反向跳变。

本版：

- Compose 占位层只显示头像圆形和三条骨架，不再提前绘制最终发件人文字。
- 无正文缓存的冷打开也从第一帧使用最终文档几何，不再先显示另一套居中加载页。
- `onPageCommitVisible` / `onPageFinished` 不再立即暴露页面。
- WebView 使用 `postVisualStateCallback` 等待当前文档的最终排版完成，再延后一帧开始短渐显。
- 每次 HTML 内容变化都有 generation 校验，旧邮件的延迟回调不能误显示到新邮件。
- 厂商 WebView 漏掉 VisualState 回调时保留 240ms、同样带 generation 校验的兜底。

## 5. 过长发件人邮箱自然换行

HTML 文档布局缓存升级为 `layout-v12`，避免继续复用旧头部样式。

- 只在发件人头部禁用 `font-synthesis`，不改变邮件正文自身的粗体规则。
- 头像使用 700 字重；发件人名称使用稳定 600 字重；邮箱与收件账户使用 400 字重。
- 名称、邮箱和收件账户取消 `nowrap`、`overflow:hidden` 与 `text-overflow:ellipsis`。
- 长地址使用 `overflow-wrap:anywhere` / `word-break:break-word` 自然换行。
- 去除旧头部右侧无用途的额外留白，正文宽度全部留给真实发件人信息。
- 头部使用最小高度而不是固定裁切高度，可随长地址行数增长。

## 6. 写邮件和删除按钮增加统一外圈阴影

新增 `FloatingCircleAction`：

- 写邮件与详情删除复用同一个圆形容器、按压缩放、1dp 半透明轮廓和 8dp 外部阴影。
- 阴影设置为不裁切，浅色模式下与左侧导航/操作 Dock 保持同一悬浮层级。
- 深色模式继续通过轮廓和容器色区分，不只依赖阴影。
