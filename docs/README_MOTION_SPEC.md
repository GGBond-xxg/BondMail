# BondMail Material 3 动画规范与实现说明

> 适用项目：`BondMail_Kotlin`
> 当前实现基线：`0.2.26.0`
> **v0.2.24.0 OAuth 连续性规则**：Gmail/Microsoft 登录与重新授权属于外部服务商交互，不得清空当前列表或删除本地账户。成功回调后只对目标账户执行一次安静刷新；取消授权应直接恢复原界面，错误提示不得泄露 Token、授权码或账户内部 ID。
> **v0.2.24.0 HTML 分类规则**：短小、带响应式标记或拥有 300–479px 内层主卡片的邮件优先保持 FLUID；只有具备足够桌面宽度证据的 480–1200px Newsletter 才进入 DESKTOP_SCALED。桌面模式关闭 WebView 二次 overview，避免已经缩放的画布再次裁切。
> **v0.2.23.0 详情顶部安全区规则**：详情正文顶部位置必须由实际状态栏 Insets、64dp 顶栏和至少 12dp 安全间距共同计算；骨架与最终 HTML 使用同一值。禁止恢复固定 96dp 假设，也禁止顶栏阴影覆盖发件人头像或首行文字。
> **v0.2.23.0 短邮件手势规则**：正文不足一屏时仍必须提供稳定的纵向拖动/过滚范围。一次触摸序列归 WebView 持有；Chrome 可见性同时参考真实 scrollY 与手指方向累计，不能因为 scrollY 很小就表现为“拖不动”。
> **v0.2.23.0 桌面邮件规则**：普通邮件使用流式手机布局；检测到 480–900px 的 newsletter 桌面画布时，保留原始列关系并整体缩放，发件人头部不得随正文缩放。桌面模式禁用逐单元格文字自动放大，避免右侧再次裁切。
> **v0.2.23.0 首次同步呈现规则**：网络层继续批量获取邮件头与小邮件正文，UI 层才渐进提交。第一条邮件应尽早进入 Room，最近首屏逐条出现，后续按小批次补齐；缓存恢复不得重复播放首次进入动画。首次历史同步和 UIDVALIDITY 重建始终属于通知基线。
> **v0.2.22.0 刷新反馈规则（覆盖 v0.2.19.0 圆形指示器规则）**：下拉手势只表现为列表跟手位移、阻尼与阈值触觉，拖动阶段不得绘制圆形/旋转进度器。越过阈值松手后列表立即回弹，由顶栏底部 3dp 线性进度条独占同步反馈；进入后台必须清除可见 busy，旧 generation 不得在下一前台会话发布错误或重新打开加载态。
> **v0.2.22.0 分组选中形变规则**：首尾外圆角为 12dp、内部相邻圆角为 5dp。邮件进入选中状态时四角统一动画到 12dp，退出选择时恢复所在首/中/尾位置；阴影、内容 clip、ripple 和滑动背景必须共享同一个实时 Shape，禁止方形长按层。
> **v0.2.22.0 未读与尾部对齐规则**：未读至少使用语义底色、主色强调和字重中的两类以上提示；深色动态主题不得只靠粗体。时间与星标属于固定宽度尾部列并统一靠右，不得由时间字符串长度改变水平位置。
> **v0.2.22.0 WebView 手势规则**：一次 ACTION_DOWN 到 ACTION_UP/CANCEL 必须由正文 WebView 持有，Compose 父层不得中途接管；回收 WebView 时清除触摸/滚动监听。移动端准备文档必须限制深层固定宽度和表格，保留纵向滚动、系统过滚与双指缩放。
> **v0.2.22.0 写信 Sheet 规则**：默认部分展开高度为可用高度约 72%，完全展开停在状态栏下方 8dp；Drag Handle 纳入 Sheet 自身测量。无论部分或完全展开，系统返回只执行一次关闭。
> **v0.2.22.0 输入与详情间距规则**：添加邮箱后缀按文本自适应并固定在同一输入框最右侧，光标必须使用可见的主题主色。详情占位和最终 HTML 都要在顶部 Chrome 下方保留一致安全区，并在发件人头部下方保留 8dp，避免骨架交接跳动。
> **v0.2.21.0 选择退出规则**：`AnimatedContent` 离场期间不得直接读取已经清空的选择集合。选择工具栏必须保存最后一次有效的非零数量，并在退出 Fade Through 完成前保持该文案；选中 Surface 恢复普通状态使用 `EffectShort` 颜色过渡，禁止出现“0 已选择”闪帧或整块背景硬切。
> **v0.2.21.0 文件夹切换连续性规则**：收件箱、星标、已发送、草稿、垃圾邮件与账户切换必须在提交可见目标前读取“账户 + 文件夹”内存/Room 快照。有缓存显示缓存，无内容显示稳定空状态；禁止先清空列表、延时后再出现“暂无邮件”，也禁止连续更新账户与文件夹时暴露中间组合。
> **v0.2.21.0 分组几何规则**：邮件、联系人、搜索结果和滑动背景共享同一个首尾 Shape 生成器。单项四角为外圆角；首项只放大顶部两角；末项只放大底部两角；中间项使用小圆角。列表删除或过滤后必须按新索引重新计算，不允许业务页面复制独立圆角常量。
> **v0.2.21.0 主题 Surface 规则**：页面画布、顶部 Chrome、内容卡片、Dock、次级分组、弹层、输入框、抽屉和 Sheet 必须通过 `BondMailSurfacePalette` 的语义角色取色。浅色、深色和 Monet 只改变底层 `ColorScheme`，业务页面不得重新散落 `surfaceContainer*` 选择，确保首页、联系人、设置、写信、详情、抽屉和添加邮箱层级一致。
> **v0.2.21.0 添加邮箱字段规则**：用户名与预设 `@domain` 属于同一输入容器。右侧域名区和展开图标固定在同一外轮廓内，菜单展开只改变边框/图标状态，不得通过两个独立输入框改变页面横向结构或产生尺寸跳变。
> **v0.2.20.0 主页面 Chrome 规则**：邮件、联系人和设置必须共享 `ObserveLazyListChromeVisibility` 的方向累计、阈值和顶部复位逻辑；底部 Dock 可见状态由 `MainTabs` 单一持有。联系人顶部搜索与 Dock 同时收回/恢复，设置没有固定标题但 Dock 仍必须响应滚动。顶部与底部位移统一调用 `animateChromeOffset`，业务页面不得复制另一套时长或缓动。
> **v0.2.20.0 搜索同步规则**：搜索收起状态必须直接属于菜单、更多、添加邮箱所在的真实顶栏行，普通滚动时不得由独立 Overlay 模拟位置。只有 Container Transform 正在展开或收回时，Overlay 才临时接管可见 Surface；源按钮在该区间隐藏但继续提供真实边界，转场结束后恢复，任意一帧只允许一个可见搜索图标。
> **v0.2.20.0 详情首帧规则**：Compose 占位层不得绘制最终发件人名称、邮箱或收件账户，避免与 WebView 的字体度量交接。必须使用无文字骨架，并在 `postVisualStateCallback` 确认最终排版后再渐显 WebView；长发件人邮箱必须换行而不是省略号截断，且发件人头部要禁用字体合成，避免字重跳变；邮件正文自身的字重规则不得被全局改写。
> **v0.2.20.0 悬浮动作规则**：底部写邮件与详情删除必须复用同一个圆形悬浮动作组件，保持相同按压缩放、外部阴影与轮廓。浅色模式阴影不得被圆形容器裁切，深色模式不得只依赖阴影区分层级。
> **v0.2.19.0 邮件正文规则**：Android WebView 默认白色画布不得直接暴露给用户。正文准备阶段必须先绘制与 App 主题一致的静态文档占位层，`onPageCommitVisible` 后只在正文区域执行 `120–180ms` 渐显；WebView 仍不得参加尺寸、共享边界或页面缩放动画。
> **v0.2.19.0 顶栏动作规则**：首页抽屉、搜索、更多和添加邮箱属于同一层级，收起状态必须使用同尺寸圆形容器、同一按压时长和缩放幅度，并与顶栏同步越过屏幕边界。详情页、写信页和列表行内操作属于次级动作，只提供标准圆形点击热区，不强制绘制永久圆底。
> **v0.2.19.0 刷新规则**：手势阶段使用跟手圆形指示器；列表归位后由不改变布局高度的顶栏 Overlay 进度线接管刷新状态。禁止同时保留两个刷新指示器，禁止用刷新区域推动文件夹栏或邮件列表。
> **v0.2.19.0 滚动安全区规则**：详情顶栏隐藏阈值必须按设备 density 换算为物理像素，并至少消耗完 HTML 顶部安全区后才能收回；不得在高密度设备上使用裸整数像素阈值造成顶部空白条。
> **v0.2.19.0 邮件布局规则**：正文根容器、引用块和桌面模板边距只做可读性归一化，根节点不得保留会推离视口的 transform/float/固定水平偏移；品牌卡片内部颜色和结构仍应尽量保留。
> **v0.2.18.0 搜索历史规则（由 v0.2.20.0 精化）**：搜索入口与展开容器必须保持连续关系且任意一帧只出现一个可见搜索图标。v0.2.20.0 起，收起按钮归属真实顶栏行，Overlay 只在 Container Transform 区间临时接管；键盘仍只能在展开完成后获取焦点，关闭时先收回容器再隐藏键盘和清空查询。
> **v0.2.18.0 顶栏规则**：首页和详情顶栏必须保留不透明 Surface 背景，并通过 `graphicsLayer.translationY` 越过屏幕边界。恢复时不得露出底下邮件文字，也不得改变列表/WebView 的测量高度。
> **v0.2.18.0 写信规则**：写信页只保留右上角发送与附件操作；抄送/密送由收件人尾部图标展开；邮箱后缀只能作为输入中的临时建议。无论 Bottom Sheet 处于部分展开还是全屏，系统返回都直接关闭到来源页面。
> **v0.2.18.0 首次详情性能规则**：WebView 不进入冷启动关键路径。首帧后仅在列表空闲窗口预热一个脱离界面的 WebView；未预热完成时先结束原生 Forward 转场再挂载 WebView。缓存数量上限为一个，内存压力下必须可释放。
> 技术栈：Kotlin、Jetpack Compose、Material 3、Navigation Compose
> 文档用途：交给后续 AI / 开发者直接实施动画重构。
> 核心目标：解决页面过渡生硬、刷新状态跳变、点击跳转缺少连续性、不同页面动画逻辑不一致的问题。

> **实施状态（v0.2.28.1）**：Motion Token、主 Tab Fade Through、邮件列表与详情 Forward/Backward、主写信按钮 Bottom Sheet、搜索框 Container Transform、添加账号 Shared X、按压反馈、首页/联系人/设置共享滚动 Chrome、详情 VisualState 渐显、单一线性刷新反馈、选择退出稳定状态、通知权限提示卡的单一高度动画与列表补位、文件夹缓存预载、12dp/5dp Gmail 分组圆角、选中 Shape 形变、WebView 完整触摸、动态详情安全区、短邮件拖动余量、桌面 newsletter 整体缩放、layout-v22 Gmail 风格详情头部与网易手机卡片恢复、图片资源归一化与手机/桌面分类、Gmail/Microsoft OAuth 与原地重新授权、K-9 式渐进首同步、批量 UID 头窗口、32 封小正文分批预取、可见视口预热与点击优先、72% 写信 Sheet、首次通知基线与前后台 generation 隔离均已接入。第 3 章保留为历史审查背景；后续修改仍必须遵守本文原则、禁止项和验收标准。

> **v0.2.17.0 写信入口硬性规则**：首页写信、联系人写信、详情回复和详情转发必须打开同一个全局 Bottom Sheet，不得分别创建导航路由或播放不同动画。默认部分展开高度约为屏幕 80%，上滑展开全屏，下滑隐藏；来源页面保持稳定，不得同时淡出、缩放或重新创建。

> **v0.2.17.0 底部 Dock 规则**：选中指示器、点击范围和 ripple 必须共享同一完整椭圆边界。独立写信按钮使用完整强调色容器，不允许在圆形按钮内部再绘制第二个选中底形。详情删除按钮使用完整错误色容器，并在真正删除前显示确认。

> **v0.2.17.0 搜索规则补充**：搜索源按钮和动画容器在任何一帧只能显示一个搜索图标。打开和关闭过程中源按钮保持透明但继续提供位置测量，动画完全停止后再恢复源按钮，禁止通过两个独立 `AnimatedVisibility` 交叉导致抽动。

> **v0.2.17.0 手势优先级**：邮件列表纵向滚动优先于卡片左右操作。方向未明确的斜向手势按纵向处理；列表拖动、fling 以及停止后的短暂 idle gate 内不得启用 SwipeToDismiss。右滑只切换已读/未读，左滑只切换星标，不允许把删除绑定到无确认的快速手势。


> **v0.2.16.1 滚动组件硬性规则**：顶部栏和底部 Dock 不得通过 `AnimatedVisibility` 从 Composition 中移除，也不得改变 `Scaffold` 的测量高度。组件必须常驻并使用 `graphicsLayer.translationY` 越过屏幕边界；滚动方向累计超过阈值后才切换一次可见状态，反向滚动需重新累计，禁止每个 WebView/List 滚动回调直接切换布尔值。

> **v0.2.16.1 写信与搜索规则**：主界面写信入口使用从底部进入/退出的 Sheet 空间关系，主页面不得同时淡出或缩放。搜索使用同一个容器从顶部搜索按钮位置插值到完整搜索框，插值范围至少包括 X/Y、宽高、圆角和内容 alpha；键盘焦点只能在容器过渡停止后请求，避免窗口尺寸变化打断动画。

> **v0.2.16.0 最高优先级决策**：本版本的邮件列表→详情不再使用 SharedTransition `sharedBounds`。真机中 Compose 共享边界与 Android WebView 首帧叠加会产生闪白，因此改用 Material 3 的 Forward/Backward 关系动画；搜索则改为 Container Transform。以下新规则覆盖文档中任何旧的冲突描述。

## 1. 参考资料

Material 3 官方资料：

- https://m3.material.io/styles/motion/transitions/transition-patterns
- https://m3.material.io/styles/motion/transitions/applying-transitions

Android 官方实现资料：

- https://developer.android.com/codelabs/material-motion-android
- https://developer.android.com/develop/ui/compose/animation/shared-elements
- https://developer.android.com/develop/ui/compose/animation/shared-elements/customize
- https://developer.android.com/develop/ui/compose/animation/shared-elements/navigation
- https://developer.android.com/develop/ui/compose/animation/quick-guide

Material Motion 的四种主要模式：

1. **Container Transform（容器变形）**：两个界面中的元素存在明确来源关系，一个容器自然扩展成另一个容器。
2. **Shared Axis（共享轴）**：两个页面存在前后步骤、层级或空间关系，可使用 X、Y、Z 轴表达方向。
3. **Fade Through（淡出穿越）**：两个内容彼此没有明确空间关系，先淡出旧内容，再淡入新内容。
4. **Fade（淡入淡出）**：同一页面中的局部元素出现或消失。

Google 官方 Reply 邮件示例与 BondMail 的场景几乎完全对应：

- 邮件列表 → 邮件详情：Forward and Backward（BondMail v0.2.16.0 项目决策）
- 写信 FAB → 写信页面：Bottom-origin sheet transition
- 搜索按钮/搜索框 → 搜索界面：Container Transform
- 不同邮箱/文件夹内容切换：Fade Through

因此，本项目不再使用“所有页面统一横向滑动”的方案，而是根据页面之间的真实关系选择动画。

## 2. 本次动画重构边界

### 2.1 必须修改

- 页面导航动画
- 邮件列表进入详情动画
- FAB 进入写信页动画
- 搜索打开与关闭动画
- 邮件、联系人、设置三个主页面切换动画
- 邮箱、文件夹、账号切换动画
- 下拉刷新动画
- 邮件详情加载动画
- 点击、按压、收藏、选择、删除等状态动画
- 返回动画和预测性返回体验
- 系统“移除动画”设置适配

### 2.2 不允许顺带修改

除动画实现所必需的接口调整外，不得修改：

- IMAP / SMTP 收发逻辑
- 邮件同步、缓存和数据库逻辑
- MIME 解析逻辑
- WebView 邮件正文加载逻辑
- 账号登录和 OAuth 逻辑
- 多语言内容
- 已有页面功能和按钮行为
- 列表分页、筛选、删除和已读逻辑

### 2.3 依赖要求

- 优先使用项目当前 Compose BOM：`2025.06.01`。
- 不要仅为了动画大版本升级 Kotlin、Compose、Navigation 或 Material 3。
- 当前版本不使用 `SharedTransitionLayout`。只有新 hero 场景经过真机验证且不包含 WebView 时，才允许局部评估共享元素 API；不得恢复全局共享作用域。
- 不引入 Lottie、第三方动画框架或大型动效资源。

## 3. 当前项目动画审查结果

### 3.1 `ui/MailApp.kt`

当前 `NavHost` 对所有路由统一使用：

- 新页面从右侧整屏进入
- 旧页面向左移动约 `1/7` 屏幕
- 时长统一 `280ms`
- 所有页面都采用相同动画

存在的问题：

- 邮件卡片进入详情、搜索、添加账号、写信等完全不同的交互，被强行表现成同一种横向页面覆盖。
- 页面之间的来源关系没有被体现，点击后像“打开另一个 App 页面”，而不是当前元素自然展开。
- 大面积整屏平移更容易暴露掉帧，尤其是正文中包含 WebView 时。
- 返回时虽然支持预测性返回，但视觉上仍是统一横向抽屉，不符合每条路由自身的关系。

### 3.2 `MainTabs`

邮件、联系人、设置之间当前通过 `when (selectedTab)` 直接替换内容：

- 底部选中指示器有弹簧动画。
- 页面内容却瞬间替换。
- 指示器和页面内容的节奏不一致，会出现“底部在移动，上面已经换完”的割裂感。

### 3.3 `ui/screens/HomeScreen.kt`

当前自定义 `ElasticRefreshContainer`：

- 保持位置约 `42dp`
- 触发阈值约 `92dp`
- 最大拉伸约 `176dp`
- 刷新时顶部显示矩形区域和 `LinearProgressIndicator`
- 列表整体向下平移

存在的问题：

- 从手指拖动状态切换到刷新状态时，代码会直接把偏移赋值为保持位置，容易产生跳一下的感觉。
- 拖动阶段与刷新阶段不是同一个视觉元素，释放后会突然从拉伸效果变成线性进度条。
- 刷新时列表持续被顶下去，页面布局不够稳定。
- 最大拉伸距离过大，容易显得像橡皮筋而不是邮箱工具类应用。
- 没有明确的“未达到阈值 / 已达到阈值”状态反馈。

当前搜索使用从顶部向下滑入的 `SearchTopSheet`，与搜索入口本身缺乏连续关系。

### 3.4 `ui/components/MessageCard.kt`

当前邮件卡片：

- 有 Material ripple。
- 没有轻微按压缩放。
- 点击后卡片与详情页没有共享容器关系。
- 收藏图标状态直接切换，缺少确认感。

### 3.5 `ui/screens/DetailScreen.kt`

当前详情页：

- 页面进入后再等待正文/WebView。
- 正文未显示时，会用居中的线性加载条覆盖正文区域。
- WebView 显示仅使用约 `90ms` alpha。

存在的问题：

- “页面进入”和“正文加载”像两个互不相关的步骤。
- 用户点击邮件后，卡片信息没有持续存在到详情页。
- 加载占位范围太大，容易产生页面先空、再突然出现正文的感觉。
- WebView 不适合参与边界尺寸动画，否则容易掉帧或闪烁。

### 3.6 `ui/screens/ComposeScreen.kt`

当前写信页面直接作为普通完整路由出现，没有体现 FAB 是写信页来源。

## 4. BondMail 动画设计原则

### 4.1 产品气质

BondMail 是高频使用的效率工具，动画应当：

- 平稳
- 克制
- 快速
- 具有空间连续性
- 不抢夺邮件内容注意力
- 不使用夸张弹跳
- 不为了“有动画”而增加动画

### 4.2 六条硬性原则

1. **动画必须解释界面关系**，不能所有页面统一套一种动画。
2. **保持布局稳定**，加载、刷新和切换不能造成内容突然跳位。
3. **直接操作跟随手指**，拖动过程中不得使用滞后的 tween。
4. **返回必须是进入动画的逆过程**，不能进入和退出使用两套无关效果。
5. **持续时间短而可感知**，常用操作不得拖沓。
6. **系统关闭动画时必须尊重设置**，不能强制播放位移和缩放。

---

## 5. 统一 Motion Token

新建：

`app/src/main/java/com/bond/mail/ui/motion/BondMotion.kt`

所有动画时长、缓动、弹簧和位移统一放在这里。业务页面不得散落新的魔法数字。

> 以下数值是针对 BondMail 的实现建议，不是声称完全复制 Material 官方内部常量。

### 5.1 时长

| Token | 建议值 | 用途 |
|---|---:|---|
| `Instant` | `0ms` | 关闭动画、无障碍降级 |
| `EffectQuick` | `90ms` | 图标按下、很小的状态反馈 |
| `EffectShort` | `120ms` | 颜色、alpha、星标反馈 |
| `ElementEnter` | `180ms` | 菜单、提示、小元素进入 |
| `FadeThrough` | `240ms` | 主 Tab、邮箱、文件夹内容切换 |
| `SharedAxis` | `280ms` | 设置流程、搜索层级、普通层级路由 |
| `ContainerTransform` | `340ms` | 邮件卡片→详情、FAB→写信 |
| `MaximumNormal` | `400ms` | 普通交互动画上限 |

规则：

- 高频点击反馈：`90–180ms`
- 内容切换：`220–280ms`
- 容器变形：`300–360ms`
- 常规交互不得超过 `400ms`
- 不设置人为等待时间来“让动画播完”

### 5.2 缓动

```kotlin
object BondMotionEasing {
    // 元素进入：前段快速响应，后段柔和停止
    val EmphasizedDecelerate = CubicBezierEasing(0.05f, 0.70f, 0.10f, 1.00f)

    // 元素退出：开始柔和，随后快速离开
    val EmphasizedAccelerate = CubicBezierEasing(0.30f, 0.00f, 0.80f, 0.15f)

    // 常规属性变化
    val Standard = CubicBezierEasing(0.20f, 0.00f, 0.00f, 1.00f)
}
```

### 5.3 弹簧

弹簧只用于：

- 用户直接拖动后的归位
- 按压释放
- 底部指示器
- 下拉刷新释放后的吸附

禁止把明显弹簧效果用于整个页面导航。

```kotlin
object BondMotionSpring {
    val PressRelease = spring<Float>(
        dampingRatio = 0.90f,
        stiffness = 700f,
    )

    val Settle = spring<Float>(
        dampingRatio = 0.86f,
        stiffness = 520f,
    )

    val NavigationIndicator = spring<Dp>(
        dampingRatio = 0.90f,
        stiffness = 500f,
    )
}
```

目标是快速收敛、基本无过冲，不允许明显“QQ 弹弹”效果。

### 5.4 位移和缩放

| 场景 | 建议值 |
|---|---:|
| Shared X 小范围位移 | `24–32dp` |
| Shared Y 小范围位移 | `16–24dp` |
| Fade Through 新内容初始缩放 | `0.98f` |
| Shared Z 新内容初始缩放 | `0.94–0.96f` |
| 邮件卡片按压缩放 | `0.985f` |
| FAB 按压缩放 | `0.94f` |
| 图标按压缩放 | `0.88–0.92f` |

禁止普通页面继续使用整屏宽度的位移，除非确实是可左右翻页的内容。

## 7. 邮件列表 → 详情页：Forward / Backward

这是 v0.2.16.0 的最终项目选择，优先级高于早期 Container Transform 方案。

### 7.1 目标效果

前进：

1. 点击邮件卡片先出现即时按压反馈。
2. 详情页从屏幕尾部方向进入，但位移仅约屏幕宽度的 `1/7`，禁止整屏飞入。
3. 邮件列表轻微缩小到约 `0.965f` 并淡出，形成“前往下一层”的空间关系。
4. 详情页主题和头部立即出现，WebView 正文仍只在自己的区域淡入。
5. 不使用共享边界，不复制卡片和详情的两个可访问节点。

返回：

1. 详情页向尾部方向退出。
2. 邮件列表从 `0.965f` 恢复到 `1f` 并淡入。
3. 返回严格是进入的逆过程。
4. 预测性返回可由 Navigation Compose 驱动同一组转场。

### 7.2 禁止重新引入邮件 sharedBounds

以下组合在真机中已确认会放大闪白和首帧重绘：

- 邮件卡片整体 `sharedBounds`
- 详情页全屏 Surface `sharedBounds`
- WebView 初始化与共享边界尺寸动画同时执行

因此 `MessageCard` 和 `DetailScreen` 不得重新添加邮件容器共享 Key。当前版本没有任何业务路由需要 `SharedTransitionLayout`；除非新场景经过真机验证，否则不得为了“更像示例”重新引入全局共享作用域。

### 7.3 WebView 处理

- WebView 不参与页面位移以外的缩放、边界和圆角变形。
- 已缓存正文可直接显示；未缓存正文只在正文区域展示占位。
- WebView 首帧用 `120ms` 左右淡入，不再与另一个共享元素动画叠加。

## 8. 写信页：统一 Bottom Sheet

### 8.1 所有入口共用一个写信抽屉

以下入口必须打开同一个全局 `ComposeScreen`：

- 首页右下角写信按钮
- 联系人邮箱地址
- 邮件详情回复
- 邮件详情转发

不得为不同来源创建不同的导航路由、不同的 ViewModel 或不同的进入动画。来源页面保留在抽屉下面，写信抽屉只从屏幕底部进入。

### 8.2 高度与手势

- 初次打开：约屏幕高度 `80%`。
- 从部分展开向上拖动：展开到全屏。
- 全屏按返回：先退回部分展开。
- 部分展开向下拖动或按返回：关闭。
- 键盘继续由系统从底部进入，不额外移动来源页面。
- Sheet 隐藏完成后再从 Composition 移除，不能先移除内容再播放空壳退出动画。

### 8.3 视觉层级

- 写信按钮整颗使用强调色容器，不在按钮内部再套第二层选中底色。
- 写信表单使用低对比 `surfaceContainerLow` / outline，不使用大面积高饱和 primary 背景。
- 发件账户、域名建议、附件标签属于辅助控件，不得抢过主题和正文输入。
- 发送按钮内部切换小型进度状态，按钮尺寸不变化。

### 8.4 附件与关闭

- 系统文件选择器属于平台界面，不叠加自定义页面转场。
- 发送成功后先让 Sheet 正常向下隐藏，再清理本次编辑状态。
- 用户主动关闭但存在未发送内容时，未来如加入草稿提示，应使用局部对话框，不改变 Bottom Sheet 空间模型。

## 9. 搜索动画：Container Transform

搜索入口与搜索页面有明确来源关系，因此不再使用 Dialog 窗口或单纯 Shared Z。

### 9.1 目标效果

- 顶栏中的圆形/圆角搜索入口扩展为顶部搜索容器。
- 容器从右上来源位置增长到全宽、约屏幕高度 `76%` 的搜索面板。
- 遮罩单独淡入，不能跟着容器一起从 56px 重测成整屏黑块。
- 关闭时容器收回右上搜索入口。
- 键盘从屏幕底部进入，不能重复触发页面动画。
- 不创建新的平台 Dialog Window，避免窗口背景闪白。

### 9.2 参数

- 展开：`340ms`，`EmphasizedDecelerate`
- 收回：`280ms`，`EmphasizedAccelerate`
- 初始容器尺寸：约 `56 × 56`
- 展开来源：`Alignment.TopEnd`
- 搜索结果列表只在容器内变化，不重新播放整个容器动画。

### 9.3 滚动组件与空间来源

首页和邮件详情遵循 “components can enter and exit from beyond the screen bounds based on a scroll gesture”：

- 向下浏览内容：顶部栏从屏幕顶部退出，底部 Dock 从屏幕底部退出。
- 反向滚动或回到列表顶部：两个组件从各自原来的边界重新进入。
- 只移动导航组件，不对 LazyColumn 或 WebView 做缩放。

组件位置必须建立连贯空间模型：

- 顶部通知从顶部进入/退出。
- 导航抽屉从左侧进入/退出。
- 底部操作区、Bottom Sheet 与键盘从底部进入/退出。
- 任何后续 AI 不得让这些组件从无关方向出现。

## 10. 主 Tab、邮箱和文件夹：Fade Through

### 10.1 邮件 / 联系人 / 设置

使用 `AnimatedContent` 替换当前直接 `when`。

节奏建议：

- 旧内容 `0–90ms`：alpha `1 → 0`
- 新内容 `90–240ms`：alpha `0 → 1`
- 新内容 scale `0.98 → 1`
- 两个页面不做横向位移
- 底部导航指示器与内容切换同时开始

示意：

```kotlin
AnimatedContent(
    targetState = selectedTab,
    transitionSpec = {
        fadeOut(tween(90, easing = BondMotionEasing.EmphasizedAccelerate)) togetherWith
            (fadeIn(
                animationSpec = tween(
                    durationMillis = 150,
                    delayMillis = 90,
                    easing = BondMotionEasing.EmphasizedDecelerate,
                ),
            ) + scaleIn(
                initialScale = 0.98f,
                animationSpec = tween(150, delayMillis = 90),
            ))
    },
    contentKey = { it },
) { tab ->
    stateHolder.SaveableStateProvider(tab) {
        // tab content
    }
}
```

注意：

- 必须继续保存每个 Tab 的滚动位置和页面状态。
- 根背景颜色必须稳定一致，避免交叉淡入时露出白色。
- 快速连续点击 Tab 时，动画必须可中断并自然转向最新目标。

### 10.2 邮箱、文件夹、账号切换

只动画邮件列表内容区域：

保持不动：

- 顶部栏
- 抽屉
- 底部导航
- FAB
- 文件夹选择控件外框

执行 Fade Through：

- 当前列表淡出。
- 新数据首帧准备好后淡入。
- 数据未到时保留稳定的内容骨架，不能先显示空状态再切成列表。
- 自动后台刷新不得触发整列表 Fade Through。

## 12. 下拉刷新动画重构

### 12.1 状态机

刷新必须明确划分：

```kotlin
sealed interface RefreshUiState {
    data object Idle : RefreshUiState
    data class Pulling(val progress: Float) : RefreshUiState
    data object Armed : RefreshUiState
    data object Refreshing : RefreshUiState
    data object Success : RefreshUiState
    data object Error : RefreshUiState
}
```

### 12.2 尺寸建议

| 参数 | 当前 | 建议 |
|---|---:|---:|
| 刷新触发距离 | `92dp` | `76–80dp` |
| 最大拉伸距离 | `176dp` | `120–132dp` |
| 刷新保持位置 | `42dp` | `52–56dp` |

整体体验应更紧凑，避免大幅橡皮筋拉伸。

### 12.3 拖动阶段

- 列表偏移直接跟随手指，不使用 tween。
- 超过正常范围后使用阻尼函数降低移动速度。
- 使用同一个圆形刷新指示器贯穿拖动、触发和刷新阶段。
- 指示器随进度变化：
  - alpha：`0 → 1`
  - scale：`0.7 → 1`
  - 圆弧长度/旋转：随 progress 变化
- progress 达到 `1f` 时进入 `Armed`。
- 首次跨过阈值时仅触发一次轻微触觉反馈。
- 用户又拖回阈值以下时返回 `Pulling`，不要重复连续震动。

### 12.4 释放阶段

当前代码不应继续直接执行：

```kotlin
pullOffsetPx = refreshHoldPx
```

必须使用同一个 `Animatable` 从当前偏移自然吸附到刷新位置：

```kotlin
offset.animateTo(
    targetValue = refreshHoldPx,
    animationSpec = BondMotionSpring.Settle,
    initialVelocity = releaseVelocity,
)
```

用户交互优先：

- 新触摸开始时停止当前归位动画。
- 动画可被再次拖动中断。
- 不允许动画与手势同时争夺 offset。

### 12.5 刷新进行中

推荐方案：

- 列表在释放后平稳回到正常位置 `0dp`。
- 圆形刷新指示器以 Overlay 方式固定在顶部安全区域。
- 列表仍可滚动。
- 不再显示顶部整块矩形和线性进度条。
- 不改变 TopAppBar 或列表的测量高度。

如果保留列表轻微下移，也不得超过约 `16–24dp`，且不能持续占用一整条顶部区域。

### 12.6 刷新结束

成功：

- 可短暂显示完成勾选 `120ms`。
- 指示器随后 `160–180ms` 淡出并缩小。
- 列表新邮件通过列表项目动画出现，不整页闪烁。

失败：

- 指示器短暂切换为错误状态。
- 然后由现有顶部提示条展示错误信息。
- 页面不得跳回顶部。

防闪烁：

- 一旦刷新指示器已经显示，建议至少可见约 `300ms`，避免极快请求造成一闪而过。
- 后台静默刷新不显示手动刷新动画。

### 12.7 Material 3 组件选择

可优先评估当前版本的 Material 3 `PullToRefreshBox` / `PullToRefreshContainer`。

只有满足以下条件才可替换自定义实现：

- 不出现二次拉伸
- 不与当前 LazyColumn overscroll 冲突
- 指示器不遮挡顶栏
- 120Hz 设备无明显卡顿
- 可以实现上述状态与完成动画

若组件行为与项目需求冲突，则保留自定义实现，但统一使用 `Animatable + NestedScrollConnection`。

---

### 12.8 邮件列表纵向/横向手势仲裁

- 先跨过触摸阈值的主方向决定本次手势归属。
- 垂直位移大于水平位移约 `1.18x` 时，本次手势锁定给列表滚动。
- LazyColumn 正在滚动以及惯性滚动停止后的 `140ms` 稳定期内，禁用 SwipeToDismiss。
- 只有新的、明确的横向手势才能触发邮件操作。

## 13. 点击与按压反馈

### 13.1 邮件卡片

按下：

- ripple 保留
- scale：`1f → 0.985f`
- 时长：`80–90ms`
- 可轻微降低 elevation，不新增阴影

释放：

- 使用快速、高阻尼弹簧回到 `1f`
- 点击导航立即执行，不能等待按压动画结束

实现建议使用 `graphicsLayer`，避免触发布局重测：

```kotlin
.graphicsLayer {
    scaleX = pressedScale
    scaleY = pressedScale
}
```

### 13.2 FAB

- 按下缩放到约 `0.94f`
- 释放后弹簧回到 `1f`
- 点击后立即启动 Bottom Sheet 的上移动画
- ripple、按压释放和 Sheet 进入必须连续，不出现先弹回、停顿、再开抽屉

### 13.3 普通图标按钮

适用：收藏、删除、回复、转发、分享、搜索。

- 按下 scale：`0.88–0.92f`
- 释放：`EffectShort`
- 不允许整个 TopAppBar 因图标状态变化重新布局

### 13.4 收藏动画

未收藏 → 收藏：

- 轮廓星标缩小
- 实心星标放大到 `1.08f`
- 回落到 `1f`
- 颜色同步过渡
- 总时长 `160–200ms`

取消收藏：

- 反向执行，但幅度更小
- 不使用旋转一整圈等夸张效果

### 13.5 底部导航

当前指示器弹簧需要降低过冲：

- dampingRatio 调整到约 `0.90f`
- stiffness 约 `500f`
- 图标颜色和大小在 `120–180ms` 内同步
- 页面 Fade Through 与指示器同帧开始
- 联系人页面首次切换不得闪白或先显示空状态

### 13.6 防重复点击

- Navigation 使用 `launchSingleTop` 或统一导航防抖。
- 同一路由正在进入时忽略重复导航。
- 不用长时间全局禁用点击。
- 防抖目标是避免重复页面实例，不是掩盖卡顿。

## 14. 顶栏、选择模式和局部状态动画

`HomeScreen` 顶栏当前使用未指定动画的 `AnimatedContent`，应明确改为 Fade Through：

- 普通顶栏先淡出。
- 选择模式顶栏淡入。
- 高度保持一致。
- 不使用默认内容位移动画。
- 进入选择模式时，被长按卡片先显示选中状态，再切换顶栏。

顶部通知条：

- 可保留小范围 Shared Y / Fade。
- 只移动提示条本身。
- 不推动整个邮件列表布局。

文件夹 Chip：

- 宽度变化不得导致整行突然重新排版。
- 标签文本应与宽度动画同步淡入。
- 频繁切换时必须可中断。

## 15. 列表项目动画

### 15.1 删除

- 卡片先沿当前滑动方向退出。
- alpha 同步降低。
- 相邻卡片使用 `animateItem` 在 `180–220ms` 内填补位置。
- 数据删除不能先让卡片瞬间消失，再播放空动画。

### 15.2 标记已读/未读

- 卡片回到原位。
- 背景颜色、字体权重视觉状态在约 `120–180ms` 内变化。
- 不重新播放整个列表进入动画。

### 15.3 新邮件出现

- 插入项轻微淡入，可伴随 `8–12dp` 的 Y 轴位移。
- 其余项目平稳让位。
- 后台同步时不要让所有现有邮件重新动画。

### 15.4 性能要求

继续保留：

- 稳定 `key`
- 合理 `contentType`
- `animateItem`
- 无多余阴影

禁止：

- 对整个 LazyColumn 做持续 scale
- 所有列表项同时执行无限动画
- 每帧改变卡片高度或文本字号

## 16. 加载动画规范

### 16.1 邮件详情

进入详情后立即显示：

- 发件人
- 主题
- 时间
- 收藏状态
- 已有头部信息

正文未准备好时：

### 16.2 联系人和设置

### 16.3 全局启动

- 启动画面退出后，主界面根背景必须已经绘制。
- 不额外添加第二层 Compose 内启动页。
- 冷启动动画不是本次重点，不能影响首屏速度。

## 17. 无障碍与“关闭动画”

必须读取系统动画缩放设置：

```kotlin
val motionScale = LocalMotionDurationScale.current.scaleFactor
val reduceMotion = motionScale == 0f
```

当系统动画缩放为 `0` 时：

- 取消页面位移
- 取消容器缩放和变形
- 取消装饰性弹簧
- 内容直接切换，或只使用非常短的 alpha / snap
- 手势拖动仍需跟手，但释放后应快速归位
- 不得依靠动画单独表达“成功、错误、选中”等信息

无障碍规则：

- alpha 为 0 的元素若不应再操作，应使用 `AnimatedVisibility` 移出 Composition。
- 动画不得改变 TalkBack 的阅读顺序。
- 共享元素只是视觉连续，不能复制出两个可访问节点。
- 触觉反馈只作为辅助，必须同时有视觉状态。

## 18. 性能规范

项目目标包含高刷新率设备。120Hz 每帧预算约为 8.3ms，因此动画实现必须克制。

### 18.1 优先方式

- `graphicsLayer` 处理 alpha、translation、scale
- `Animatable` 处理手势偏移
- `AnimatedVisibility` 处理真正出现/消失
- `AnimatedContent` 处理内容替换
- Shared Transition 只作用于少量关键元素
- 稳定 State、稳定 Key、避免无关重组

### 18.2 禁止方式

- 动画期间持续重新创建 WebView
- 对 WebView 边界、字号或 HTML 高度做动画
- 大面积 blur
- 动态修改多层阴影
- 整个列表每帧重测尺寸
- 每个邮件卡片同时运行无限 shimmer
- 一个点击同时叠加两种页面过渡
- 使用 `delay()` 模拟动画节奏

### 18.3 测试版本

动画流畅度必须使用项目现有 `performance` 构建进行最终对比，不能只根据 Debug 包判断。

建议：

```bash
./gradlew assemblePerformance
```

Android 帧统计示例：

```bash
adb shell dumpsys gfxinfo com.bond.mail reset
# 完成一轮：切 Tab、打开邮件、返回、刷新、写信
adb shell dumpsys gfxinfo com.bond.mail
```

同时使用 Android Studio JankStats / System Trace 检查：

- 邮件卡片进入详情
- 预测性返回
- WebView 首次显示
- 下拉刷新释放
- 主 Tab 快速切换

## 22. 明确禁止的实现

后续 AI 不得采用以下方案：

1. 继续给所有页面统一配置 `slideInHorizontally(fullWidth)`。
2. 为了“更明显”把普通过渡延长到 500ms 以上。
3. 对整页使用明显弹跳、回弹或过冲。
4. 让页面导航等待 ripple 或按压动画播放完成。
5. 对 WebView 做容器变形、缩放或高度动画。
6. 用 `delay()` 人为制造分段动画。
7. 刷新状态直接硬赋值偏移造成跳变。
8. 加载时先显示空页面，再突然替换成完整内容。
9. 切换文件夹时让顶栏、底栏和 FAB 一起淡出。
10. 每个页面单独定义不同的时长和缓动常量。
11. 为动画升级整个项目依赖并引入新的业务回归。
12. 通过关闭点击、降低刷新率或牺牲功能来掩盖掉帧。
13. 为写信入口分别创建多套路由/动画，或重新引入已经移除的 FAB sharedBounds。

## 25. v0.2.21.0 状态退出与缓存切换补充规范

### 25.1 选择模式退出

选择模式的离场内容必须使用“最后一次有效状态”完成淡出。最后一个条目取消勾选后，不允许在退出动画仍可见时把标题重新组合为 `0 已选择`。

实现要求：

- 选择数量为正数时更新最近一次有效数量；
- 数量变为 0 时立即启动选择工具栏离场，但离场副本继续显示最近一次有效数量；
- 普通顶栏以 Fade Through 进入，选择顶栏以 Fade Through 退出；
- 邮件卡片选中 Surface 使用 `EffectShort` 颜色过渡恢复；
- 不使用 `delay()` 掩盖重组时序，也不通过延迟清空选择集合来维持旧文字；
- 系统动画缩放为 0 时直接完成状态切换，不保留透明但可点击的选择层。

### 25.2 文件夹和账户切换

文件夹切换不得把“数据读取”表现成空白页面。目标内容应在提交可见选择前从内存快照或 Room 缓存确定：

1. 内存快照存在：立即显示；
2. 无内存快照：同步读取 Room；
3. Room 有内容：直接显示缓存内容；
4. Room 已确认为空：直接显示稳定的“暂无邮件”；
5. 后续网络同步通过 Room Flow 更新当前内容。

同时改变账户与文件夹时，必须把两者视为一个目标状态，抑制 `旧账户 + 新文件夹` 或 `新账户 + 旧文件夹` 的中间组合。快速连续切换应取消上一次预加载任务，只提交最后一次目标。

### 25.3 Surface 动画边界

`BondMailSurfacePalette` 负责静态视觉层级，页面不得通过独立颜色动画制造不同主题。主题切换由 Material 3 颜色系统统一驱动；邮件选中、未读等局部状态可以执行短颜色过渡，但页面、顶部 Chrome、抽屉和底部 Dock 不应在正常导航中各自使用不同的淡色目标。
