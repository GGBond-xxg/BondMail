# 一、产品定位

这是一个轻量级多账户邮箱客户端。

中文名称：

```text
邮箱
```

简体中文以外的应用名称：

```text
Mail
```

产品目标：

- Android 优先，先把 Android 原生版本做稳定；
- 后续 iOS 单独开发，不要求本次共享代码；
- Gmail / Material 3 风格；
- 默认蓝色主题；
- 支持 Android 莫奈动态取色；
- 支持浅色、深色、跟随系统；
- 多账户、统一收件箱；
- 本地优先，启动和打开邮件要快；
- 不依赖自建服务器即可完成基础收发；
- 后台不得长期维持大量 IMAP 连接；
- 尽量控制内存、耗电、网络请求和数据库写入次数。

当前阶段不做：

- 企业邮箱通用配置；
- 任意自定义 IMAP/SMTP 服务器；
- 长期驻留一个完整 UI 进程来收信；
- 同时为多个账户保持永久 IMAP IDLE 长连接。

# 二、必须支持的邮箱服务

## 2.1 首批邮箱

| 服务商 | 账户类型 | 登录方式 | IMAP | SMTP | 常用后缀 |
|---|---|---|---|---|---|
| QQ Mail | 个人邮箱 | 授权码 | `imap.qq.com:993` | `smtp.qq.com:465` | `qq.com`、`foxmail.com` |
| 163 Mail | 个人邮箱 | 客户端授权码 | `imap.163.com:993` | `smtp.163.com:465` | `163.com` |
| 126 Mail | 个人邮箱 | 客户端授权码 | `imap.126.com:993` | `smtp.126.com:465` | `126.com` |
| Gmail | 个人邮箱 | OAuth 2.0 | `imap.gmail.com:993` | `smtp.gmail.com` | `gmail.com`、`googlemail.com` |
| Outlook / Hotmail / Live | 微软个人邮箱 | OAuth 2.0 | `outlook.office365.com:993` | `smtp.office365.com:587 STARTTLS` | `outlook.com`、`hotmail.com`、`live.com`、`msn.com` |
| Microsoft 365 | 微软账户 | OAuth 2.0 | `outlook.office365.com:993` | `smtp.office365.com:587 STARTTLS` | Microsoft 账户域名 |
| iCloud Mail | 苹果邮箱 | App 专用密码 | `imap.mail.me.com:993` | `smtp.mail.me.com:587 STARTTLS` | `icloud.com`、`me.com`、`mac.com` |
| Yahoo Mail | 个人邮箱 | App 专用密码 | `imap.mail.yahoo.com:993` | `smtp.mail.yahoo.com:465` | `yahoo.com`、`yahoo.com.cn`、`yahoo.co.jp` |

## 2.2 网易邮箱特殊处理

163、126 邮箱需要保留网易客户端身份兼容逻辑。

要求：

- 登录前后发送网易要求的 IMAP Client ID / 客户端安全身份；
- 登录失败时给出明确提示；
- 不要把“网易拒绝第三方客户端访问”统一显示成普通密码错误；
- 提示用户检查：
  - 是否开启 IMAP/SMTP；
  - 是否使用客户端授权码；
  - 是否重新生成授权码。

## 2.3 Gmail 和微软邮箱

Gmail、Outlook、Hotmail、Live、Microsoft 365 必须使用 OAuth。

不要使用普通密码或模拟授权码方案代替 OAuth。

Token 要求：

- Access Token 和 Refresh Token 放入 Android Keystore 支持的安全存储；
- Token 失效时支持刷新；
- 刷新失败时提示重新授权；
- 日志中不得打印 Token。

# 三、Kotlin 原生技术架构

## 3.1 推荐技术栈

```text
Kotlin
Jetpack Compose
Material 3
Navigation Compose
Room
DataStore
WorkManager
Android WebView
Android Keystore 支持的加密凭证存储
Android Notification API
Android Sharesheet
Android Storage Access Framework
Coroutines + Flow
```

邮件协议层需要独立封装，避免 UI 直接依赖具体 IMAP/SMTP 库。

建议模块：

```text
app/
├── data/
│   ├── database/
│   ├── datastore/
│   ├── credentials/
│   ├── imap/
│   ├── smtp/
│   ├── html/
│   └── repository/
├── domain/
│   ├── model/
│   ├── usecase/
│   └── sync/
├── background/
│   ├── MailSyncWorker
│   ├── MailSendWorker
│   └── MailNotificationManager
├── ui/
│   ├── shell/
│   ├── inbox/
│   ├── detail/
│   ├── compose/
│   ├── contacts/
│   ├── accounts/
│   └── settings/
└── MainActivity.kt
```

## 3.2 架构原则

- UI 使用 Compose；
- 数据库使用 Room；
- 设置使用 DataStore；
- 账户密码、授权码、Token 不写入 Room；
- 账户同步串行执行；
- UI 首先显示本地缓存，再后台刷新；
- 网络操作不阻塞主线程；
- 邮件列表不要因为同步而整页切换成 Loading；
- 高频状态更新使用乐观更新；
- 服务端失败时回滚本地状态；
- HTML 邮件、附件、同步和通知分别封装；
- 不要让一个超大 ViewModel 管理全部功能。

# 四、应用导航和整体布局

## 4.1 底部导航

手机底部固定三项：

```text
邮件
联系人
设置
```

要求：

- 当前页面状态可保持；
- Drawer 打开时必须覆盖底部导航；
- Drawer 打开后不能继续点击底部导航切换页面；
- 关闭 Drawer 后才能操作底部导航；
- 不允许出现“切换页面后回来 Drawer 仍然停留在打开状态”的问题。

## 4.2 平板布局

平板使用响应式布局：

- 左侧：账户和文件夹；
- 中间：邮件列表；
- 右侧：邮件详情；
- 手机保持单栏导航；
- 平板不要简单把手机列表纵向拉宽；
- 邮件列表和详情可以同时显示；
- 平板详情模式不要创建重复 Hero 标签。

## 4.3 顶部栏

邮件首页顶部只保留一行，顺序固定：

```text
菜单 ｜ 全部账户/当前账户下拉 ｜ 搜索 ｜ 刷新 ｜ 添加账户
```

要求：

- 左上角菜单按钮紧凑，不要过大的圆形背景；
- 所有按钮垂直对齐；
- 搜索、刷新、添加账户按钮尺寸一致；
- 账户名称可点击下拉；
- 下拉内容包括“全部账户”和每一个已绑定账户；
- 不再额外显示第二行“全部账户”筛选；
- 长按图标时不要出现方形或椭圆形阴影；
- 点击反馈必须与圆形按钮形状一致。

# 五、首次启动和添加账户

## 5.1 首次启动

没有账户时显示首次引导，不要只显示转圈或错误页。

引导内容：

- App 名称；
- 多账户统一收件箱说明；
- 本地保存说明；
- 授权信息由系统安全存储保护；
- “添加邮箱”按钮；
- 支持邮箱服务商图标。

## 5.2 选择邮箱类型

添加账户第一步显示服务商列表：

- QQ；
- 163；
- 126；
- Gmail；
- Outlook / Hotmail / Live；
- Microsoft 365；
- iCloud；
- Yahoo。

每个服务商必须有对应图标。

开启莫奈动态取色后：

- 服务商图标；
- 账户头像；
- 邮件发件人图标；

统一跟随莫奈主题。

设置中只显示一个开关：

```text
莫奈动态取色
```

不要再单独显示“部件图标取色”或“邮件图标莫奈取色”。

## 5.3 邮箱地址输入

用户选择邮箱服务商后，不应再要求完整输入固定后缀。

示例：选择 126 邮箱时：

```text
左侧输入：用户名
右侧固定显示：@126.com
```

QQ：

```text
用户名 ｜ @qq.com
```

右侧可切换：

```text
@qq.com
@foxmail.com
```

微软：

```text
用户名 ｜ @outlook.com ▼
```

可切换：

```text
@outlook.com
@hotmail.com
@live.com
@msn.com
```

要求：

- 后缀必须完整显示，不能变成 `@qq...`；
- 后缀文本优先，图标空间不足时可以移除下拉箭头；
- 可粘贴完整邮箱地址，自动拆分用户名和后缀；
- 固定服务商不显示无意义的自定义服务器设置；
- Microsoft 365 可支持其账户域名，但仍使用微软固定服务器和 OAuth；
- 不开放任意 IMAP/SMTP 主机、端口输入。

## 5.4 账户显示名称

支持自定义显示名称，例如：

```text
163 Mail → 网易邮箱
QQ Mail → 工作 QQ
```

规则：

- 最多 14 个 Unicode 字符；
- 添加账户和编辑账户时都必须限制；
- 保存层再次防御性截断；
- 空名称时回退到邮箱地址或服务商名称；
- 不允许超长名称破坏邮件列表布局。

## 5.5 账户连接流程

账户绑定步骤要拆开处理：

1. 校验输入；
2. 测试 IMAP；
3. 测试 SMTP；
4. 保存账户；
5. 保存凭证；
6. 返回账户已添加；
7. 首次同步作为后续独立步骤。

重要：

- 账户已经成功保存后，即使首次同步失败，也不能回滚账户；
- 同步失败要显示错误，但账户仍保留；
- 不在日志输出授权码；
- Android 自动备份不得恢复无法解密的旧凭证；
- 账户凭证必须独立命名空间或独立别名保存。

# 六、账户管理

账户管理页必须支持：

- 查看所有账户；
- 查看邮箱地址；
- 查看自定义显示名称；
- 根据邮箱域名显示正确服务商图标；
- 莫奈动态图标；
- 启用/停用账户；
- 编辑显示名称；
- 查看上次同步时间；
- 显示最近同步错误；
- 删除账户；
- 添加账户。

删除账户时：

- 删除本机数据库中的该账户邮件；
- 删除本机授权码或 Token；
- 不删除服务器邮箱；
- 给出明确说明。

账户数量不做限制，但同步必须串行，不能同时为所有账户建立连接。

# 七、邮件首页和邮件列表

## 7.1 文件夹快捷栏

支持：

- 收件箱；
- 已发送；
- 草稿；
- 星标；
- 垃圾邮件；
- 垃圾箱；
- 自定义文件夹入口。

样式：

- 未选中项只显示图标；
- 当前选中项展开图标和文字；
- 文字相对整个按钮真正居中；
- 不要出现文字偏上、偏左或偏右；
- 莫奈模式下仍要保留清晰边框；
- 深色模式下边界不能消失。

## 7.2 邮件列表卡片

邮件列表使用圆角卡片，风格与联系人列表一致。

每条邮件结构：

```text
[发件人头像+邮箱账户标识]  发件人名称             收藏
                          邮件主题               时间
```

左侧：

- 圆形发件人图标；
- 邮箱账户名称嵌入头像底部；
- 标识宽度始终等于上方圆形头像直径；
- 标识跟随宽松、标准、紧凑密度一起缩放；
- 标识与头像轻微重叠；
- 文本必须完整显示；
- 空间不足时缩小文本，不主动显示省略号；
- 头像和底部账户标识应作为同一个动画整体。

中间：

- 第一行发件人；
- 第二行邮件主题；
- 默认不显示正文摘要，减少拥挤。

右侧：

- 右上角收藏星标；
- 右下角时间；
- 邮箱名称不放在右侧。

## 7.3 未读邮件样式

未读邮件不能只改变时间颜色。

必须同时具备明显但不过度的区分：

- 发件人加粗；
- 主题适度加粗；
- 左侧主题色强调条或圆点；
- 主题色边框；
- 轻微背景差异；
- 星标和时间仍保持可读。

## 7.4 列表密度

设置中支持：

- 宽松；
- 标准；
- 紧凑。

密度变化要明显，包括：

- 卡片高度；
- 头像尺寸；
- 上下间距；
- 字体和身份标识尺寸。

## 7.5 滑动操作

方向固定：

- 左滑：标记已读 / 未读；
- 右滑：删除。

要求：

- 滑动后立即回弹；
- 本地先乐观更新；
- 服务器成功后保留；
- 服务器失败时恢复原状态并提示；
- 不允许“右滑删除后刷新又回来”的假删除。

后续服务器语义：

- 普通删除优先移动到 Trash；
- Trash 中支持永久删除；
- 垃圾邮件支持恢复到正常文件夹；
- 服务器不支持移动时才使用 `\Deleted` 和 EXPUNGE 兼容方案。

## 7.6 搜索

搜索范围：

- 发件人名称；
- 发件人邮箱；
- 主题；
- 正文。

要求：

- 搜索界面不要与顶部组件黏在一起；
- 搜索结果卡片之间有固定间距；
- 搜索结果复用主列表卡片样式；
- 搜索打开和关闭时不重置收件箱；
- 无结果显示友好空状态。

# 八、邮件同步

## 8.1 本地优先

启动时：

1. 立即读取本地数据库或轻量缓存；
2. 显示现有邮件；
3. 后台开始同步；
4. 新邮件逐封插入列表；
5. 不清空旧列表；
6. 不显示全屏 Loading。

## 8.2 同步策略

要求：

- 多账户串行；
- 单账户按文件夹同步；
- 优先获取最新 UID；
- 小批次下载；
- Flutter 参考实现批次为 8 封；
- 每批写入数据库后立即更新 UI；
- 同步过程中列表可以继续操作；
- 不提前下载全部附件；
- 不在主线程解析超大 MIME；
- 避免每一封邮件都重写完整缓存 JSON。

## 8.3 需要识别的服务器文件夹

通过 IMAP Special-Use、Attributes 和常见名称识别：

```text
INBOX
SENT
DRAFTS
JUNK / SPAM
TRASH
```

常见名称兼容：

- Sent、Sent Messages、已发送；
- Drafts、草稿箱；
- Junk、Spam、垃圾邮件；
- Trash、Deleted、垃圾箱、已删除、废纸篓。

后续必须保存：

- 服务器真实文件夹名；
- canonical 类型；
- UIDVALIDITY；
- UID；
- flags；
- 最近同步位置；
- 文件夹未读数和总数。

## 8.4 已读、星标和删除

已读：

- `\Seen`；
- 本地立即更新；
- 失败回滚。

星标：

- `\Flagged`；
- 本地立即更新；
- 失败回滚。

删除：

- 收件箱删除优先移动到服务器 Trash；
- Trash 中执行永久删除；
- 支持 UID MOVE 时优先使用；
- 不支持 MOVE 时兼容 COPY + `\Deleted` + EXPUNGE；
- UIDPLUS 可用时使用 UID EXPUNGE；
- 不支持时使用安全兼容方案。

## 8.5 已发送

SMTP 发送成功后：

- 创建本地 Sent 记录；
- 通过 IMAP APPEND 写入服务器 Sent 文件夹；
- APPEND 失败不能误报发送失败；
- 应显示“发送成功，但保存到已发送文件夹失败”；
- 后续同步可重新发现并去重。

# 九、后台收信和通知

## 9.1 测试频率

为了方便实体机测试，设置中提供：

```text
1 分钟
5 分钟
10 分钟
15 分钟
```

行为说明：

- App 在前台时可按设置精确轮询；
- App 在后台时使用 WorkManager；
- Android 后台调度可能延迟；
- 正式发布默认 15 分钟；
- 1/5/10 分钟主要用于测试或 App 进程仍存活时；
- 不要通过永久 Flutter/Dart 进程实现；
- 不要为每个账户单独启动一个 Worker；
- 一个 Worker 内按账户串行同步。

## 9.2 后台任务要求

- 只拉取新增邮件头和必要摘要；
- 不下载全部附件；
- 不渲染 WebView；
- 不加载远程图片；
- 检测到新邮件后写入 Room；
- 只为真正新增邮件发送通知；
- 网络失败使用退避；
- 同一时刻只允许一个同步任务；
- App 手动刷新与后台 Worker 要有互斥锁；
- 避免重复通知同一 UID。

## 9.3 通知权限

建议时机：

- 首次绑定账户成功后；
- 或设置页手动开启通知时。

要求：

- 权限被拒绝时，后台同步仍然继续；
- 只是无法显示系统通知；
- 设置页显示当前权限状态；
- 可以跳转系统通知设置；
- 不要把“没有通知权限”错误地当成“无法收邮件”。

- 只显示“收到新邮件”；
- 显示发件人和标题。

后续预留：

- 只显示发件人；
- 显示标题；
- 显示部分正文；
- 自定义通知隐私级别。

- 打开对应邮件；
- 已删除邮件则回到收件箱；
- 多账户通知正确定位账户和文件夹。

# 十一、HTML 邮件显示

## 11.1 渲染原则

HTML 邮件使用 Android WebView。

不要使用简单富文本组件替代复杂营销邮件。

要求：

- 保留原始邮件布局、背景、字体颜色和链接颜色；
- 不要全局强制覆盖成 App 文本颜色；
- 深色模式下只修复实际低对比度文字；
- 不破坏邮件自身深色模板；
- Coinbase、Bybit 等营销邮件在浅色和深色模式下都要清晰；
- 图片、按钮、表格、验证码和正文都要完整显示。

## 11.2 低对比度修复

检测：

- 文本实际颜色；
- 文本实际背景；
- 继承背景；
- 透明背景；
- 深色容器；
- 浅色容器。

只在对比度确实过低时替换颜色。

不要出现：

- 黑字叠黑底；
- 浅灰字叠白底；
- 主题切换后文字变成不可见；
- 莫奈开启后邮件正文颜色被错误染色。

## 11.3 图片兼容

支持：

- 普通 `src`；
- `srcset`；
- `data-src`；
- `data-original`；
- `data-lazy-src`；
- 协议相对地址；
- `cid:` MIME 内嵌图片；
- data URI；
- 加载完成后重新测量正文高度。

## 11.4 远程图片策略

设置项：

```text
始终自动加载
仅 Wi-Fi 自动加载
从不自动加载
```

邮件内按钮：

```text
本次加载
```

“本次加载”要求：

- 点击后该封邮件的图片加载状态要缓存；
- 关闭后再次打开同一封邮件，图片仍然显示；
- 不要再次显示“未加载图片”；
- 缓存可以按邮件 ID + 内容版本保存；
- 邮件内容变化时使旧缓存失效；
- 后台同步不主动加载图片。

## 11.5 再次打开秒开

第一次打开邮件：

- 允许显示短暂加载状态；
- 完成 HTML、图片和高度计算后缓存。

再次打开：

- 直接显示已缓存内容；
- 不显示加载圈；
- 不先显示无图版再切换有图版；
- 不重新创建一个空 WebView；
- 不出现正文闪白；
- 最近打开邮件采用有限 LRU 缓存；
- Flutter 参考实现缓存最近 8 封。

建议缓存：

- 净化后的 HTML；
- 图片允许状态；
- 页面实际高度；
- 正文文本；
- CID 映射；
- 已加载图片资源或 WebView 缓存；
- 内容 hash。

## 11.6 邮件显示完整

需要解决：

- 长邮件底部被截断；
- 表格固定宽度导致右侧缺失；
- 邮件正文底部巨大空白；
- 图片加载后高度未更新；
- 动态 DOM 内容未重新测量；
- 邮件只显示上半段；
- 纯附件邮件预留大片空白。

高度策略：

- 页面内容根节点；
- body；
- documentElement；
- 最后一个可见内容节点；
- 图片加载事件；
- ResizeObserver；
- MutationObserver；
- 合理最大高度；
- 不以邮件模板声明的巨大固定高度直接作为最终高度；
- 忽略不可见占位元素和空容器。

# 二十一、缓存策略

## 21.1 启动缓存

- App 启动立即读取 Room；
- 不等待网络；
- 账户和最近邮件应快速显示；
- 不需要再额外维护一份巨大 JSON 邮件副本；
- Compose + Room Flow 可直接作为本地数据源。

## 21.2 邮件详情缓存

缓存最近打开邮件：

- 完整消息；
- 净化后 HTML；
- 正文高度；
- 远程图片状态；
- CID 内嵌资源映射；
- 内容 hash。

使用有限 LRU，避免无限占用。

## 21.3 品牌缓存

品牌匹配结果最多保留数百项。

- 可清理；
- 不保存授权信息；
- 文件名冲突安全处理；
- 支持系统选择保存位置。

# 二十二、性能要求

## 22.1 邮件列表

- LazyColumn；
- 稳定 key；
- 避免每个 item 重复解析品牌规则；
- 避免每个 item 重建日期格式器；
- 避免监听整个同步对象；
- 只观察 item 所需字段；
- 卡片不使用无意义高成本阴影；
- 滑动时不要同步写数据库；
- 批量或防抖保存状态。

## 22.2 同步

- 账户串行；
- MIME 解析放到后台线程；
- 数据库批量事务；
- 小批次更新；
- 不重复下载已知 UID；
- 仅重新下载仍有未解析 CID 的邮件；
- 网络断开快速停止；
- 防止手动同步和 Worker 重叠。

## 22.3 WebView

- 重用有限缓存；
- 不为列表预创建 WebView；
- 返回列表时及时释放非缓存 WebView；
- 避免同一 WebView 同时绑定两个界面；
- 图片加载后防抖测量；
- 不无限监听 DOM。

## 22.4 后台

- 不保持多个常驻 IMAP 连接；
- 不在后台解析所有历史邮件；
- 不在后台下载附件；
- 不在后台创建 Compose UI；
- Worker 超时后安全关闭连接。
