# 桌面小组件

从 **设置 → 桌面小组件** 选择默认尺寸，再选择账号、主题和显示内容，点击“添加到桌面”。也可以长按桌面，在系统小组件列表中找到 BondMail。桌面不支持 App 内直接添加时，使用后一种方式。

## 已实现

- 2×2 未读卡片、4×2 最近邮件、4×4 邮件列表三个默认入口，均可由桌面调整大小。
- 每个实例独立绑定一个已启用账号；首次默认采用最近选择的账号和 App 主题。后续切换 App 账号不会更改已有小组件。
- MIUI / HyperOS、Material 3、Liquid Glass 三种风格，分别支持浅色、深色和跟随系统。
- 真实本地收件箱、完整未读计数、最近最多 6 封邮件；不会把最近 6 封的未读数量当成总数。
- 点击标题进入对应账号的收件箱，点击邮件打开详情，写信使用该账号作为发件账户。失效账号或不属于该账号的邮件不会跳转到其他账号。
- 刷新按钮复用现有账号同步流程，按账号合并连续点击；不同小组件不会导致同一账号并发同步。
- 未读数量、发件人、主题、摘要、时间、写信和刷新入口开关。
- 正常显示、隐藏摘要、隐藏主题与摘要三种隐私模式。隐藏内容在数据转换和桌面绑定两层过滤，不进入无障碍说明，也不通过透明度隐藏。
- 配置页展示真实缓存预览；修改保存后刷新实例。在 App 的小组件列表或支持重配的桌面菜单中可重新配置。
- 无账号、空收件箱、账号删除/停用、离线、同步失败及读取失败状态。
- 简体中文、繁体中文、英文和系统字体缩放。未读邮件有标记及无障碍说明，不单独依靠颜色。

## 主题和尺寸

| 风格 | 材质与颜色 | 邮件标记 |
| --- | --- | --- |
| MIUI / HyperOS | 干净浅色/深色卡片、蓝色操作色、细分隔线 | 紧凑列表未读圆点、大卡片本地品牌图标 |
| Material 3 | Android 12+ 系统动态配色，旧版本使用标准 M3 色板；圆角色调容器 | 彩色首字母 / 本地品牌图标和未读标记 |
| Liquid Glass | 中性透明玻璃层与细高光边缘，直接透出手机壁纸 | 首字母和未读标记 |

桌面小组件不支持直接运行 App 内普通 Compose / Backdrop 控件。Glass 不添加背景图片或蓝色装饰底，透明区域由桌面直接合成其后的壁纸；不读取壁纸，不提供实时模糊、折射或色散。App 内的 Glass 调节不会改变桌面材质。

“2×2 / 4×2 / 4×4”是默认网格目标，不是固定像素大小。不同桌面、屏幕密度和字体设置会给出不同空间：窄卡片优先显示未读数量；列表根据空间显示 1～6 封；默认采用发件人和主题两行；开启摘要后只在较高的卡片出现第三行；刷新按钮位于较高且足够宽的卡片。字体放大时减少行数，极窄卡片会隐藏次要文字。邮件标题和地址过长时省略，不缩小全部文字以强行塞入固定行数。

## 数据和后台更新

数据从现有 Room 数据库读取，不重新保存邮件内容。新增查询只选取列表字段并限制 6 行，未读数独立 COUNT。无需数据库版本升级，也没有新增第三方依赖。

Room 中邮件或账号改变、保存设置、桌面调整尺寸、系统更新请求、重启/升级、语言及网络变化都会请求本地重绘。写入事件合并后交给 WorkManager；本地重绘不会触发邮箱同步。桌面每 30 分钟的保底更新也只读取缓存。邮件网络同步继续使用 App 原有的后台机制；手动刷新只同步对应账号。

离线/同步失败保留本地邮件。账号移除或停用后清空内容，提示重新配置。配置只持久化账号 ID、主题与开关，删除小组件时删除实例配置；多实例互不覆盖。后台执行时间仍由 Android 和厂商省电策略决定，不保证固定秒级刷新。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `widget/WidgetConfig.kt` | 实例配置、序列化、尺寸/字体预算 |
| `widget/WidgetData.kt` | Room 一致性快照、隐私转换 |
| `widget/WidgetRenderer.kt` | RemoteViews、配色、透明材质缓存、本地品牌图标、点击 PendingIntent |
| `widget/MailWidgetProvider.kt` | 三种 Provider、系统事件、合并更新与账号刷新 Worker |
| `widget/WidgetConfigActivity.kt` | 配置、预览、添加到桌面、已有实例管理 |
| `data/db/Daos.kt` | 限量邮件查询和账号未读计数 |
| `MainActivity.kt`、`ui/MailApp.kt` | 验证实例和邮件归属后进入对应页面 |
| `res/layout/widget_*.xml`、`res/xml/widget_*.xml` | 桌面布局及 Provider 元数据 |

Kotlin 路径均相对 `app/src/main/java/com/bond/mail/`。测试在 `app/src/androidTest/java/com/bond/mail/MailWidgetTest.kt`。

## 验证范围与限制

实机使用 vivo V2310 / Android 15（API 35）；未操作小米。验证桌面添加、不同主题实例同时存在、写信账号、邮件详情、重配和隐私显示。自动测试使用独立内存数据库验证两账号隔离、超出列表长度的未读计数、已读/删除更新、账号失效、配置持久化与清理，并检查三主题浅深色、5 种尺寸及 1/1.5/2 倍字体、摘要开关下的 180 组布局、按钮间距、最后一行边界、隐私文本和 Glass 中心透明度。

最低版本仍为 Android 8.0 / API 26。API 26～30 使用横竖屏 RemoteViews 回退布局，API 31+ 支持桌面提供的实际尺寸集合；本轮没有其他 Android 版本和其他 Launcher 的实机覆盖，不将其标记为已验证。

无需补充图片、账号密钥或设计素材。小组件显示最近邮件摘要，完整列表、附件和邮件操作留在 App 内。

设计与实现依据：[Android 小组件概览](https://developer.android.com/develop/ui/views/appwidgets/overview)、[自适应布局](https://developer.android.com/develop/ui/views/appwidgets/layouts)、[小组件配置](https://developer.android.com/develop/ui/views/appwidgets/configuration)。
