## 邮件打开“双闪”修复

根据本次真机录屏逐帧检查，未缓存邮件原来的显示流程包含多段连续空窗：

1. WebView 池未预热时，先等待约 280ms 才挂载 Chromium；
2. 正文尚未取得时，前 300ms 只显示空页面；
3. HTML/WebView 准备阶段又延迟 450ms 才显示占位；
4. Chromium 已提交可见帧后再额外保持 300ms；
5. 最终内容再渐显 300ms。

这些延迟叠加后，视觉上会出现“进入空页 → 内容壳出现 → 正文再次出现”的两次闪动。本版改为单阶段显示：

- 进入详情的第一帧立即绘制原生稳定壳层，包括主题、头像、发件人、地址、收件账户、日期和正文摘要；不再先暴露空白背景。
- WebView 冷启动挂载等待由完整 `SharedAxis 280ms` 缩短为 `EffectQuick 90ms`，仍给导航目的页一个稳定原生帧，减少 Chromium 与页面转场争抢同一帧。
- 删除正文占位的 300ms 延迟和 WebView 占位的 450ms 延迟。
- 删除 Chromium 可见帧提交后的额外 300ms 停留。
- 未缓存邮件只执行一次 `180ms` 短交叉渐显；原生壳层在 WebView 完全可见前始终垫在下方，因此不会露出 WebView 的白色/空白挂载帧。
- 已展示过的缓存邮件继续直接挂载并瞬时切换，不重播首次渐显。
- Android“移除动画”开启时，正文切换使用瞬时显示，不强行动画。
- 页面 generation、渲染进程恢复、远程图片开关和 WebView 复用逻辑保持不变。

## Binance 等表格邮件排版修复

对比本项目与 Apple Mail 截图后确认，Binance 事务邮件的正文属于完整的约 600px 桌面表格画布。旧逻辑虽然识别到了外层桌面画布，但又被内部按钮或页脚的小宽度表格判定为“手机卡片”，最终选择 `FLUID`。发件人自己的移动端 CSS 随后把社交图标单元格改为块级元素，造成图标从横排变成竖排，正文结构也与原始邮件不同。

本版调整：

- 对 `binance.com`、其子域名，以及 `binance.us`/子域名，检测到可靠桌面画布时优先选择 `DESKTOP_SCALED`。
- 保留邮件原始列、按钮、页脚和社交图标结构，只把整张画布按当前屏幕宽度缩放一次，行为更接近 Apple Mail。
- 新增通用“图标行”结构识别：一行中多数单元格为小图片/SVG、且几乎没有正文时，强制保持 `table-row/table-cell`，避免其他发件人的移动端规则把社交链接、支付标志等拆成竖列。
- 纯图标页脚不再参与“手机主内容卡片”和“桌面画布”的宽度评分，避免 320px 社交图标表误导整封邮件的布局模式。
- 网易 163/126 等已明确使用手机卡片的事务邮件仍强制走 `FLUID`，不会因这次修改重新缩成中央小卡片。
- 深色模式实现未改：仍由 Android WebView 的算法深色化处理原始浅色邮件，保留本项目现有的夜间模式优势。

## 缓存与兼容

- Prepared HTML 缓存键从 `layout-v25` 升级为 `layout-v26`，覆盖安装后旧的内存排版结果不会复用。
- Room 仍为 v8，不新增数据库字段，不清除账户、邮件、正文、附件、OAuth 或授权码数据。
- MIME parser 仍为 v8，附件解析、Sent 去重和远端删除逻辑不变。

## 真机回归重点

1. 冷启动后首次打开一封尚未打开过的新邮件：第一帧已有主题/发件人壳层，随后正文只进行一次短渐显，不出现连续两次闪动。
2. 返回列表后立即重开同一封邮件：不出现全白、全空或重复渐显。
3. 快速连续打开不同邮件：占位内容必须属于当前邮件，不得短暂显示上一封正文。
4. 打开 `do-not-reply@ses.binance.com` 的充值成功邮件：Logo、标题、按钮、免责声明和页脚完整；社交图标横向排列，不再逐个竖排。
5. 浅色、深色和动态取色分别检查 Binance 邮件；深色模式应继续保持可读，链接和品牌色不应被正文背景遮挡。
6. 回归 GitHub、Cloudflare、Bybit、Grab、163/126 邮件，确认宽度、图片、引用、滚动和远程图片开关没有退化。
