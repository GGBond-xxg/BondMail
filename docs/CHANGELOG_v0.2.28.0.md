# BondMail v0.2.28.0

## 邮件打开速度改为“视口预热 + 点击优先”

本版不按发件人或品牌决定正文下载速度。正文加载统一使用以下顺序：

1. Room 中已经存在正文时直接命中本地缓存；
2. 首页滚动停止后，预热当前可见邮件以及少量前后项；
3. 用户点击邮件时，当前邮件立即切换到高优先级加载通道；
4. 详情页继续复用同一个 message mutex，避免点击预热与详情请求重复下载；
5. 初次同步仍采用 K-9 式批量 Header、渐进列表和小正文分批预取。

具体调整：

- 首次同步的小正文预热窗口从最近 24 封提高到最近 32 封，仍按 8 封一批并保留 128 KiB 自动下载上限。
- 已有账户重新启动后，不再等 20 秒只预热 2 封；改为界面稳定约 1.8 秒后预热最近 12 封。
- 首页根据 `LazyListState` 取得稳定视口，滚动停止后预热可见邮件并向前后少量扩展；快速 fling 期间不会持续发送 IMAP 请求。
- 点击邮件前先启动高优先级正文准备，然后立即进入详情；详情页与准备任务共享正文锁和 Room 缓存。
- `PreparedMailDocument` 内存缓存由 32 份扩大到 64 份，减少频繁打开不同邮件时重复执行 Jsoup 清理和布局分析。
- 单实例 WebView 复用池保留最后一封已经视觉提交的本地文档。返回后立即重新打开同一封邮件时，可直接复用已栅格化页面；打开其他邮件仍以透明状态加载，不会闪出旧正文。

邮件首次打开仍可能因服务器、正文大小、MIME 结构或远程图片速度不同而存在差异，但这些差异不再来自针对某个发件人的下载分支。网易域名安全回退只参与 HTML 手机/桌面布局分类，不影响 IMAP 正文调度。

## Gmail 风格详情内容层级

- 详情顶部栏背景改为与页面背景一致，移除独立的 Chrome 色块和阴影。
- 返回、星标和更多按钮保持原位置和功能，底部回复/转发/分享/删除 Dock 不改动。
- 顶部栏不再显示单行截断主题；邮件主题移动到正文区域顶部，使用可换行的大标题。
- 主题下方继续显示头像、发件人、发件地址和收件账户，主题区与发件人区使用页面背景，邮件原始 HTML 从其下方开始。
- 正文尚未下载或 WebView 尚未提交时，加载页立即显示真实主题和发件人信息，只在正文区域显示进度反馈，降低“点进去像没反应”的感觉。
- HTML 准备缓存升级为 `layout-v22`，旧的详情头部布局缓存自动失效。

## 同一邮件的渲染复用

- WebView 池继续只保留一个实例，避免多 WebView 常驻导致内存上涨。
- WebView 仅在 `onPageCommitVisible` / visual-state callback 确认后记录可复用 content key。
- 同一邮件、同一主题、同一远程图片状态和同一主题配色再次打开时直接显示保留页面。
- 内容、主题、解析版本、图片权限或配色变化时，content key 不同，仍会重新加载正确文档。
- Chromium 渲染进程退出时会清除保留 key 并销毁死亡实例，不会复用失效页面。

## 保留的实现

- 批量 UID / ENVELOPE / FLAGS Header 获取与 K-9 式渐进列表。
- Header / Body 分离、128 KiB 小正文批量预取和大 Newsletter 按需下载。
- FLUID / DESKTOP_SCALED 双布局、Cloudflare 桌面画布缩放、网易事务邮件手机宽度恢复。
- 163/126 原地更改授权码、Gmail/Microsoft OAuth、XOAUTH2 与 R8 规则。
- 通知权限用户主动请求、拒绝持久化和列表补位动画。
